# R1c-1 — Events: the planning the band runs on

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The committee can enter a whole season — thirteen rehearsals, the gigs,
the AG, a two-day musical weekend — from a real screen, and every member can see
it. Attendance is **not** in this plan; R1c-2 adds it on top.

**Architecture:** One new table (`events`), six routes, four screens. The only
piece with real subtlety is time: the database stores UTC, the band lives in
Europe/Zurich, and a rehearsal is at 10:00 in Fribourg no matter where the
browser is. Task 1 builds that discipline before anything can get it wrong.

**Tech Stack:** Laravel 13 + Sanctum session auth + MariaDB 10.3; React 19 +
TypeScript + Tailwind 4 + TanStack Query through the orval-generated client.
Tests: PHPUnit (in Docker) and Vitest + MSW.

---

## How to read this plan

**Test code is given in full and is meant to be transcribed.** A test is a
specification; a concrete assertion can be checked against reality and argued
with.

**Implementation is stated as requirements, not as code.** This is deliberate
and it is a project decision, recorded at the head of the R1b plan: verbatim
implementation code written before the code exists produced *every* defect found
while building that plan's Task 1 — an idempotency test that could not fail, a
duplicate-key collision with reference data the plan itself introduced, and a
phpunit assumption the plan's own step falsified.

So: **read the requirements, verify them against the code as it actually is,
then write the implementation.** Keep the test names, the literals, the routes
and the error tokens exactly; everything else is yours to derive.

**Expect this plan to be stale in places.** R1b's was, in four separate ways,
each recorded at the head of that file. If a step contradicts the code, the code
wins — and say so in the commit message.

## Running the tests

**The Laravel suite runs in Docker.** A native green run is not a Docker green
run — that has already shipped two red tests to this branch.

```bash
docker compose exec -w /var/www/html/_api web php artisan test --filter=SomeTest
```

In Git Bash, prefix with `MSYS_NO_PATHCONV=1` or the `-w` argument is rewritten
to a Windows path and Docker rejects it. PowerShell is unaffected.

**Run the web suite from PowerShell, not Git Bash.** Git Bash reports a
lowercase drive letter and Vitest 4 keys module resolution off it, producing
"Vitest failed to find the runner" across every file. It looks catastrophic and
is not.

```powershell
npm run test:web
npm run typecheck
```

## Global constraints

- **English everywhere except rendered UI text.** Columns, JSON bodies, error
  codes, comments, this file. French only in what a browser paints.
- **The API error contract is `{error, code, fields[]}`.** Every new `code` and
  every new `fields[].reason` MUST have French copy in `web/src/i18n/fr.ts` or
  `api/tests/Feature/ApiErrorVocabularyTest.php` fails.
- **`web/src/api/generated/` is generated.** Change the controller, run
  `npm run openapi && npm run generate:api`, commit the result.
- **Never `disabled` on a button.** `aria-disabled` plus an early return in the
  handler. The one exception is a control inert for the whole lifetime of a
  form — see R1b's role checkboxes.
- **Every interactive control clears 44px.** `Button` and `Input` carry
  `min-h-touch`; anything hand-rolled must too.
- **No bare tables on phones.** Cards below `md`.
- **Use the four spacing tokens** — `tight` / `related` / `block` / `section`.
- **Scramble cannot see through `->map(closure)`.** A list built that way
  generates `string[]` in the client, silently. Use a Resource plus a typed
  private method with a `@return list<...>` docblock for anything non-scalar.

## Task 1: The band's clock

**This task exists because `config('app.timezone')` is `'UTC'`.** Everything
else in this plan depends on getting time right, and the failure mode is
silent — a season that is an hour out, discovered by somebody arriving at the
wrong time.

The rule: **the database stores UTC; the band's wall clock is Europe/Zurich.**
A rehearsal is at 10:00 in Fribourg whether you read the page from Fribourg or
from Sydney, so Europe/Zurich is not "the user's timezone" — it is a property of
the band, and it is therefore a constant in code rather than anything read from
a request.

**Files:**
- Create: `api/app/Support/BandTime.php`
- Test: `api/tests/Unit/BandTimeTest.php`

- [ ] **Step 1: Write the failing test**

Create `api/tests/Unit/BandTimeTest.php`:

```php
<?php

namespace Tests\Unit;

use App\Support\BandTime;
use PHPUnit\Framework\TestCase;

class BandTimeTest extends TestCase
{
    public function test_it_composes_a_date_and_a_wall_clock_time_into_utc(): void
    {
        // 5 September 2026 is CEST, UTC+2. Ten in the morning in Fribourg is
        // eight in the morning UTC, and that is what the column must hold.
        $composed = BandTime::compose('2026-09-05', '10:00');

        $this->assertSame('2026-09-05 08:00:00', $composed->utc()->format('Y-m-d H:i:s'));
    }

    public function test_it_honours_the_winter_offset(): void
    {
        // 5 December is CET, UTC+1. The SAME wall-clock time is a DIFFERENT
        // instant, which is the entire reason this class exists rather than a
        // hard-coded "+2 hours" somewhere.
        $composed = BandTime::compose('2026-12-05', '10:00');

        $this->assertSame('2026-12-05 09:00:00', $composed->utc()->format('Y-m-d H:i:s'));
    }

    public function test_the_composed_instant_reads_back_as_the_wall_clock_time(): void
    {
        // The round trip a member actually experiences: what was typed is what
        // the planning shows.
        $composed = BandTime::compose('2026-12-05', '10:00');

        $this->assertSame('10:00', $composed->setTimezone(BandTime::ZONE)->format('H:i'));
    }

    public function test_the_start_of_today_is_midnight_in_fribourg_not_in_utc(): void
    {
        // Used by the upcoming/past split. At 00:30 Fribourg time it is still
        // 22:30 UTC the previous day, so a UTC-based "start of today" would
        // drop this evening's event out of the planning two hours early.
        $startOfToday = BandTime::startOfToday();

        $this->assertSame('00:00:00', $startOfToday->setTimezone(BandTime::ZONE)->format('H:i:s'));
    }
}
```

- [ ] **Step 3: Write the class**

**Implement `api/app/Support/BandTime.php`.**

Requirements:

- A `ZONE` constant holding `'Europe/Zurich'`. It is a constant and not a config
  key on purpose: a server whose `.env` disagreed would shift a whole season,
  and there is no case for two servers of this application disagreeing about
  where Fribourg is. Say that in the docblock.
- `compose(string $date, string $time): CarbonImmutable` — takes `Y-m-d` and
  `H:i`, interprets them **in `ZONE`**, and returns the instant. Immutable
  rather than `Carbon`, because a returned mutable date that a caller modifies
  in place is a bug nothing catches.
- `startOfToday(): CarbonImmutable` — midnight in `ZONE`, as an instant.
- Do not change `config('app.timezone')`. Storing UTC is correct; this class is
  how the two meet.

            'ends_at' => '2026-09-05 10:00:00',

        $this->assertFalse($event->is_public);
    }

    public function test_the_public_flag_is_a_boolean_not_an_integer(): void
    {
        // Without the cast this arrives in JSON as 1/0 and the generated
        // TypeScript types it as number, which every consumer then has to

    }
}

<?php

namespace Tests\Feature;

use App\Models\Event;
use App\Models\Member;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Tests\TestCase;

class EventIndexTest extends TestCase
{
    use RefreshDatabase;

    private Member $member;

    protected function setUp(): void
    {
        parent::setUp();
        // An ordinary player. Reading the planning needs no permission —
        // everybody in the band needs to know when the next rehearsal is.
        $this->member = Member::factory()->inSection()->create();
    }

    public function test_an_anonymous_caller_is_refused(): void
    {
        // 401, not 403: the planning is members-only in R1c (C1), and an
        // anonymous caller has not failed a permission check — they have not

        $this->getJson('/api/events')->assertStatus(401)->assertJson(['code' => 'not_authenticated']);
    }

    public function test_it_lists_upcoming_events_soonest_first(): void
    {
        Event::factory()->create(['title' => 'Plus tard', 'starts_at' => now()->addDays(20)]);
        Event::factory()->create(['title' => 'Bientôt', 'starts_at' => now()->addDays(2)]);

        $response = $this->actingAsMember($this->member)->getJson('/api/events')->assertOk();

        $this->assertSame(['Bientôt', 'Plus tard'], array_column($response->json(), 'title'));
    }

    public function test_past_events_are_absent_by_default(): void
    {
        // C4: "the planning" means what is ahead. By next carnival the full
        // list is a hundred rehearsals to scroll past on a phone.
        Event::factory()->past()->create(['title' => 'Déjà joué']);
        Event::factory()->create(['title' => 'À venir']);

        $response = $this->actingAsMember($this->member)->getJson('/api/events')->assertOk();

        $this->assertSame(['À venir'], array_column($response->json(), 'title'));
    }

    public function test_past_returns_only_the_history_newest_first(): void

import { weekdayDatesBetween } from "./eventDates";

test("it lists every Saturday in a range, inclusive of both ends", () => {
  // 5 September 2026 is a Saturday.
  const dates = weekdayDatesBetween("2026-09-05", "2026-09-26", 6);
  expect(dates).toEqual(["2026-09-05", "2026-09-12", "2026-09-19", "2026-09-26"]);
});

  const dates = weekdayDatesBetween("2026-09-01", "2026-09-13", 6);
  expect(dates).toEqual(["2026-09-05", "2026-09-12"]);

  // The real season runs September to January and the clocks change in
  // October. A naive "add 7 * 24 hours" drifts by an hour and eventually
  // lands on a Friday.
  const dates = weekdayDatesBetween("2026-10-24", "2026-11-07", 6);
  expect(dates).toEqual(["2026-10-24", "2026-10-31", "2026-11-07"]);
});

test("a range containing no matching weekday is empty, not an error", () => {
  expect(weekdayDatesBetween("2026-09-07", "2026-09-11", 6)).toEqual([]);
});

test("a backwards range is empty rather than infinite", () => {
  // The loop guard. Without it a from-date after the to-date spins forever and
  // the tab locks up, which is a far worse failure than an empty list.
  expect(weekdayDatesBetween("2026-09-26", "2026-09-05", 6)).toEqual([]);
