# SPA Clean Slate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete the old PHP front end and every piece of tooling that points at it, rewire the build/dev/deploy machinery around a React SPA, and leave a repository that is `api/ + web/ + tools/ + docs/` and builds a deployable artifact.

**Architecture:** `api/` (Laravel) is untouched but for deleting the session bridge it asks to have deleted. A new Vite + React + Tailwind build in `web/` produces `dist/build/`, into which `tools/build.mjs` then copies Laravel as `api-laravel/`. Apache serves `index.html` for every non-`/assets/` path that is not `/api/*` or `/sanctum/*`. Everything that can be done without deleting `app/` is done first, so the one unavoidable large commit is as small as it can be.

**Tech Stack:** React 19.2, Tailwind 4.3 (CSS-first), Vite 8, TypeScript, Vitest + Testing Library, Playwright 1.62, Laravel 11.

**Spec:** `docs/superpowers/specs/2026-08-28-spa-clean-cutover-and-mocks-design.md`, amending `docs/superpowers/specs/2026-07-27-frontend-spa-cutover-design.md`.

```ts
import tailwindcss from "@tailwindcss/vite";
import react from "@vitejs/plugin-react";
import { defineConfig } from "vite";

/**
 * The SPA build.
 *
 * `root: 'web'` makes web/index.html the entry. `base: '/'` because the shell
 * is served from the document root, unlike the old per-page bundles which were
 * served from /assets/dist/.
 *
 * outDir is dist/build/ — the deploy artifact — because tools/build.mjs copies
 * the Laravel API in beside this output afterwards. dist/build/ is git-ignored
 * and fully regenerated by whichever build ran last, and tools/build.mjs starts
 * by removing it, so the two builds cannot corrupt each other.
 *
 * Vite resolves vite.config.js BEFORE vite.config.ts, so while app/'s config
 * still exists every Vite invocation in package.json passes --config
 * explicitly. Task 6 deletes vite.config.js and the flags go with it.
 */
export default defineConfig({
  root: "web",
  base: "/",
  plugins: [react(), tailwindcss()],
  build: {
    outDir: "../dist/build",
    emptyOutDir: true,
    sourcemap: false,
  },
});
```

- [ ] **Step 2: Create `web/src/i18n/index.ts`**

A typed port of `translateApiError`, taking the `ApiError` that `web/src/api/http.ts` already throws rather than a raw body.

```ts
import i18next from "i18next";

import type { ApiError, ApiErrorField } from "../api/http";
import { fr } from "./fr";

const FALLBACK = "Une erreur est survenue. Veuillez réessayer.";

i18next.init({
  lng: "fr",
  fallbackLng: "fr",
  resources: { fr: { translation: fr } },
});

export type TranslatedError = {
  message: string;
  fields: { field: string; message: string }[];
};

/**
 * Turns the API's machine tokens into French. This is the ONLY place in the
 * system where French is computed from an API response: `code` and
 * `fields[].reason` are stable English tokens and are never shown raw. An
 * unknown token falls back to a generic message rather than leaking an English
 * identifier or an i18next key onto a French screen.
 */
export function translateApiError(error: Pick<ApiError, "code" | "fields">): TranslatedError {
  const fields = error.fields.map((entry: ApiErrorField) => {
    const fieldKey = `fields.${entry.field}`;
    const label = i18next.exists(fieldKey) ? i18next.t(fieldKey) : entry.field;
    const reasonKey = `validation.${entry.reason}`;
    const reason = i18next.exists(reasonKey) ? i18next.t(reasonKey, entry.params ?? {}) : FALLBACK;
    return { field: entry.field, message: `${label} ${reason}` };
  });

  const codeKey = `errors.${error.code}`;
  return {
    message: i18next.exists(codeKey) ? i18next.t(codeKey) : FALLBACK,
    fields,
  };
}
```

```js
/**
 * The KEYS a dotenv file declares, sorted. Values are never read, returned or
 * logged — a server's .env holds real credentials, and this check only ever
 * needs to know which keys exist.
 */
export function envKeys(source) {
  const keys = new Set();
  for (const line of source.split(/\r?\n/)) {
    const match = line.match(/^\s*(?:export\s+)?([A-Za-z_][A-Za-z0-9_]*)\s*=/);
    if (match) keys.add(match[1]);
  }
  return [...keys].sort();
}

/** Keys the code expects that the server lacks, and keys it no longer expects. */
export function compareEnvShape(expected, actual) {
  const have = new Set(actual);
  const want = new Set(expected);
  return {
    missing: expected.filter((k) => !have.has(k)),
    extra: actual.filter((k) => !want.has(k)),
  };
}

/**
 * Compares the target's api-laravel/.env key set against api/.env.example
 * before anything is uploaded, so a deploy that would land code expecting a key
 * the server has never been given fails here instead of 500ing every /api/*
 * request afterwards.
 */
export async function checkEnvShape(client, remoteRoot) {
  const expected = envKeys(readFileSync('api/.env.example', 'utf8'));
  const tmpDir = mkdtempSync(path.join(tmpdir(), 'lc-env-'));
  const tmpEnv = path.join(tmpDir, 'env');
  try {
    try {
      await client.downloadTo(tmpEnv, `${remoteRoot}/api-laravel/.env`);
    } catch (err) {
      // A brand-new environment, before its one-time hand provisioning. The API
      // cannot run either way, so blocking adds no protection here — report
      // skipped and let the caller warn, exactly as the config check did.
      return { ok: true, skipped: true, reason: err.message, missing: [], extra: [] };
    }
    const drift = compareEnvShape(expected, envKeys(readFileSync(tmpEnv, 'utf8')));
    return { ok: drift.missing.length === 0 && drift.extra.length === 0, ...drift };
  } finally {
    rmSync(tmpDir, { recursive: true, force: true });
  }
}
```

This keeps `checkConfigShape`'s exact download mechanism (`client.downloadTo` into a `mkdtempSync` directory) and its exact return shape, including the `skipped`/`reason` pair the caller already branches on — so `cli.mjs` needs a renamed import and new message text, nothing structural. Keep the existing `mkdtempSync`, `tmpdir`, `path`, `readFileSync` and `rmSync` imports; drop only the `php-parser` one.

- **`.env.*` use `FTP_PASSWORD`, and the deploy CLI reads `FTP_PASS`.** That is deliberate and already documented; inject `FTP_PASS` for a one-off command rather than editing the files.
- **Never run `docker compose up` directly.** `npm run dev` generates `dist/overlay/docker/.htaccess` first; without it Docker creates a *directory* at that path and the `web` container refuses to start.
- **The Laravel suite is not part of `npm run check`.** It needs the stack: `docker compose exec -w /var/www/html/api-laravel web php artisan test`.
- **In Git Bash, prefix `docker compose exec` with `MSYS_NO_PATHCONV=1`** or the `-w /var/www/html/api-laravel` argument is rewritten to a Windows path and Docker rejects it. PowerShell is unaffected.
